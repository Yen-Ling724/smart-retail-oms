## 2. 架構調整建議（相較原企劃）
1. **資料庫直接用 Supabase**：免在 Windows 安裝 PostgreSQL，網頁上就能看資料表。
2. **後端不放 Vercel**：Vercel 適合前端；Express 常駐伺服器放 Render 較單純（免費方案閒置會休眠，第一次開啟需等約 30–50 秒）。
3. **登入自己做（bcrypt + JWT）**：角色分 `admin`（總部）、`staff`（門市人員）。顧客端導購不需登入。
4. **防超賣**：用資料庫交易 + 條件式更新（`UPDATE ... SET reserved = reserved + n WHERE available >= n`），更新筆數為 0 就整筆訂單回滾。
5. **AI 不亂編**：後端先查資料庫，只把查到的商品資料交給 Claude；Claude 用「工具呼叫」查資料，查不到就回答「目前沒有資料」。
6. **無 AI 金鑰也能展示**：保留「關鍵字篩選」備援模式，避免金鑰用完網站就壞掉。
7. **公開展示要能重置**：訪客可能亂改資料，提供「重置示範資料」按鈕或每日自動重置。

```mermaid
  product_prices { bigint id PK; text product_id FK; int list_price; int sale_price; timestamptz valid_from; timestamptz valid_to }
  stores { text store_id PK; text name; text city; text address }
  inventory { text store_id PK,FK; text product_id PK,FK; int on_hand; int reserved; int display; int damaged; int in_transit }
  customers { bigint id PK; text name; text phone; text address }
  orders { text order_no PK; bigint customer_id FK; text store_id FK; text fulfillment; text status; int total; timestamptz created_at }
  order_items { bigint id PK; text order_no FK; text product_id FK; int qty; int unit_price }
  inventory_transactions { bigint id PK; text store_id FK; text product_id FK; text type; int qty_change; text ref_order_no; timestamptz created_at }
  promotions { bigint id PK; text name; text type; int discount; timestamptz start_at; timestamptz end_at }
  system_events { bigint id PK; text event_type; jsonb payload; timestamptz created_at }
  users { bigint id PK; text email; text password_hash; text role; text store_id FK }
```
可銷售 = `on_hand - reserved - display - damaged`（在途 `in_transit` 不計入）。

> 比原企劃多兩張表：`users`（登入權限）、`promotion_products`（促銷與商品多對多）。
